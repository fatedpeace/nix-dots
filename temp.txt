# Current Quickshell Knowledge

## `PanelWindow`

I'm using a `PanelWindow` for the Dynamic Island.

Important distinction:

* `PanelWindow` controls the **window/screen behavior**.
* A `Rectangle` inside it controls the **visual appearance**.

Mental model:

```text
PanelWindow
├── position
│   ├── anchors
│   └── margins
├── size
│   ├── implicitWidth
│   └── implicitHeight
└── Rectangle
    └── visual island
```

`PanelWindow` is a Quickshell type.

`Rectangle` is a Qt Quick type.

Imports:

```qml
import Quickshell
import QtQuick
```

# PanelWindow Properties Learned

## `implicitWidth` / `implicitHeight`

These define the size of the PanelWindow.

For example:

```qml
implicitWidth: 500
implicitHeight: 40
```

means the PanelWindow is 500×40.

## `margins`

Margins offset the window from an anchored screen edge.

If:

```qml
anchors.top: true
```

then:

```qml
margins.top: 8
```

moves it 8px away from the top.

General rule:

```text
top anchor    → margins.top
bottom anchor → margins.bottom
left anchor   → margins.left
right anchor  → margins.right
```

The Quickshell docs say margins only apply to edges with anchors.

You can set one side directly:

```qml
margins.top: 5
```

instead of:

```qml
margins: [0, 5, 0, 0]
```

Also, QML property declarations use `:` rather than `=`:

```qml
margins.top: 5
```

not:

```qml
margins.top = 5
```

## `exclusiveZone`

This controls how much space the compositor reserves for the panel.

For development, I'm currently deliberately using:

```qml
exclusiveZone: 40
```

so I can clearly see the island.

Eventually, because this is supposed to be a floating Dynamic Island rather than a traditional bar, I expect to experiment with:

```qml
exclusiveZone: 0
```

so applications don't get pushed down.

Important distinction:

* `implicitHeight` → size of the Quickshell window
* `exclusiveZone` → screen space reserved by the compositor

## `anchors`

`PanelWindow` can be attached to screen edges.

Current positioning:

```qml
anchors.top: true
```

I don't want left/right anchors because I don't want the island to stretch across the screen.

# Rectangle / QML Concepts Learned

## QML Types

This:

```qml
Rectangle {
}
```

is **not a function**.

`Rectangle` is a QML type.

Writing:

```qml
PanelWindow {
    Rectangle {
    }
}
```

creates a hierarchy:

```text
PanelWindow
└── Rectangle
```

The Rectangle is a child object of the PanelWindow.

It doesn't "modify" the PanelWindow itself.

## Property Binding

QML properties can depend on other properties.

Example:

```qml
width: parent.width
```

means the width stays bound to the parent's width.

This is different from just manually assigning a fixed number.

The binding updates automatically if the referenced property changes.

## `parent`

For a child QML visual object, `parent` refers to its visual parent.

So:

```qml
Rectangle {
    width: parent.width
}
```

means the Rectangle's width follows its parent.

## Anchors

I learned that:

```qml
anchors {
    top: parent.top
    left: parent.left
    right: parent.right
    bottom: parent.bottom
}
```

can be shortened to:

```qml
anchors.fill: parent
```

The latter anchors all four sides to the parent.

# Current Visual Result

The red Rectangle is now visible and has successfully become a pill.

Using:

```qml
radius: height / 2
```

works because the Rectangle is 40px high:

```text
height = 40
40 / 2 = 20
radius = 20
```

This produces the pill shape.

Using `height / 2` is preferable to hardcoding `20` because if the island's height changes later, the radius can follow automatically.
